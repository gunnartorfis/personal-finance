## Findings considered and rejected

- **Redirect/return URLs derived from `request.url` Host** (`open-banking/connect:40`,
  `callback:50`, `billing/checkout:38`, `renew:84`): LOW confidence. Vercel validates Host
  on its platform and Enable Banking pins registered redirect URLs; not worth a plan
  unless the app leaves Vercel. Revisit then (use a configured `APP_BASE_URL`).
- **`pnpm audit --prod`**: 3 moderate, 0 high/critical — below the report threshold. All
  transitive under `@neondatabase/auth` → `better-auth`; the better-auth OAuth-state
  advisory (GHSA-wxw3-q3m9-c3jr) is worth tracking for the next Neon Auth bump, but Neon
  Auth's callback here is wrapped and the app's own open-banking flow does its own
  state+intent binding.
- **Middleware not covering API routes for auth**: by design (routes self-guard via
  `requireHousehold()`); verified every route actually does.
- **AI `reasoning` shown un-localized/as-is**: documented v1 decision (CONTEXT.md); no
  HTML sink exists.

## Clean bill of health (verified, for the record)

Tenant isolation (householdId stamped/filtered everywhere, `Omit` on insert types, scoped
`findById` → foreign id = 404), invite tokens (256-bit, SHA-256 at rest, expiry + verified
email + seat cap), cron auth (constant-time bearer, rejects when unset), webhook HMAC
(timing-safe, verified before any effect), open-banking callback (state cookie + single-use
intent), SQLi (all Drizzle `sql` templates parameterized; no `sql.raw`), XSS (single
`dangerouslySetInnerHTML` is dev-config CSS in `components/ui/chart.tsx`), no secrets
committed or logged, checkout price server-derived, free-cap enforced server-side, GDPR
export household-scoped with tokens stripped.
